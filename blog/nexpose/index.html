Rapid7 Nexpose Vulnerability Scanner

本地部署的漏洞扫描器

一款强大的漏洞管理解决方案，可在整个环境中提供全面的资产可见性，同时协助风险的优先级排序与修复。

工作原理

收集

通过对整个网络的实时覆盖，随时掌握风险情况。

核心功能

助你在关键时刻采取行动的漏洞扫描软件。

实际风险评分

传统的 1-10 CVSS 分数往往会标记成千上万个“高危”漏洞。我们的漏洞扫描器采用实际风险评分（Real Risk Score），提供更具可操作性的洞见 (sysin)。该评分不仅考虑漏洞的存在时间，还包括公开利用代码或恶意软件工具包等因素，1-1000 的评分范围可突显最有可能被攻击者利用的漏洞，助你优先处理真正关键的问题。

结合强大的标签系统，还可自动优先处理对你的业务最关键的系统。

自适应安全

“被动扫描”常伴随大量误报和陈旧数据，源自不频繁的数据导出。而借助 Nexpose 的自适应安全功能，一旦新设备或新漏洞访问你的网络，即可实现自动检测与评估。

结合与 VMware 和 AWS 的动态连接，以及与 Sonar 研究项目的集成，Nexpose 为你提供真正的实时环境监控。

策略评估

加强系统防护与发现并修复漏洞同样重要。

Nexpose 提供内置的策略扫描，帮助你依据 CIS 和 NIST 等主流标准对系统进行基准评估 (sysin)。直观的修复报告提供逐步指导，说明哪些操作将最显著提升合规性。

修复报告

修复报告列出可降低最大风险的前 25 项行动，并附有清晰的操作指南。

还可为管理层创建趋势报告，展示安全项目的投资回报与进展情况。

🆕 新增：

  • 扫描模板支持基于凭据的预端口发现（Credentialed Pre-Port Discovery）。扫描模板现在在 Asset Discovery（资产发现）下新增 Use credentialed pre-port discovery（使用基于凭据的预端口发现）选项（默认关闭）。启用后，扫描引擎会通过 Scan Assistant、SSH 或 Windows 凭据，直接从每个目标获取开放端口信息，从而绕过针对这些资产的基于网络的 Nmap 端口扫描。对于没有匹配凭据或身份验证失败的目标，将自动回退到标准 Nmap 扫描，因此不会造成任何资产覆盖范围的丢失。
    • 重要提示：主机会报告其在本地监听的所有端口，而不会感知主机与扫描引擎之间存在的防火墙或网络控制措施 (sysin)。在启用此选项之前，请检查您的防火墙规则。在网络高度分段的环境中，基于网络的端口扫描可能仍然是更好的选择。此功能可以通过 Administration > Scan Templates > Asset Discovery 启用，也可以通过 REST API 将 discovery.asset.prePortDiscovery 参数设置为 true 来启用。

✨ 改进：

  • 策略内容更新：
    • 新增对 CIS Mozilla Firefox ESR GPO Benchmark v1.0.0 的支持
    • [CIS] 将 CIS Microsoft Windows Server 2022 Benchmark 内置策略内容从 v4.0.0 更新至 v5.1.0
    • [CIS] 将 CIS Microsoft Windows Server 2025 Benchmark 内置策略内容从 v1.0.0 更新至 v2.1.0
    • [CIS] 将 CIS Amazon Linux 2 Benchmark 内置策略内容从 v3.0.0 更新至 v4.0.0

🐞 修复：

  • 修复了在某些情况下，自定义策略合规性扫描能够成功完成，但报告集成资产数量为零的问题。这会导致扫描结果无法记录到控制台中的任何资产上。该问题现已解决——自定义策略合规性扫描完成后，资产现在可以正确完成集成。
  • 修复了 使用 Shell Command Checks 的 CIS Benchmark ARF 报告无法打开的问题。针对使用 Shell Command Checks（Shell 命令检查）的 CIS Benchmark（例如 CIS PostgreSQL 17）生成的 Asset Reporting Format（ARF）报告，在浏览器中打开时会产生 XML 错误，导致报告无法使用。该问题现已解决，ARF 报告现在可以正常打开。
  • 控制台 CLI 重置密码命令失败。命令行重置密码功能会因数据库错误而失败，导致管理员无法通过控制台 CLI 重置用户密码。该问题现已解决，重置密码命令现在可以成功完成。
  • Discovery Connections 页面加载失败。当某个发现连接的状态缺失或不完整时 (sysin)，可能会导致整个 Discovery Connections（发现连接）表无法加载，使用户无法查看或管理任何连接。该问题现已解决——无论单个连接处于何种状态，该页面现在都可以正常加载。
