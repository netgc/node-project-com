on-premises and cloud virtual desktops

Run virtual desktops and apps with confidence

  • 灵活的云部署选项

  • 最佳的最终用户体验

  • 赋能混合劳动力

新增功能

Horizon 8 2609 | 2026 年 10 月 22 日

Horizon 8 2609 | 22 OCT 2026 Server Build: 8.20.0-38966629614

借助 Horizon 8，IT 部门可在数据中心内运行远程桌面和应用程序，并将这些桌面和应用程序交付给员工。最终用户可以获得熟悉的个性化环境，并可以在企业或家庭中的任何地方通过任意数量的设备访问此环境。通过将数据集中到数据中心，管理员可以进行控制并提高效率和安全性。

重要说明

  • Horizon 2609 Agent 同时支持 2603 ESB Server 和 2609 Server 版本。有关详细信息，请参阅不同版本 Horizon 8 组件的兼容性矩阵。
  • 对于使用 Horizon 8 2512 和 Nutanix 自动化桌面池或场的客户：2603 中的配对机制发生了变化，因此 Connection Server 和 Agent 必须同时更新到 2603 或更高版本，后续配置操作才能正常进行。有关如何为有限的向后兼容性做好环境准备，请参阅 KB 文章 6001315。如果已经升级到 2512.1 或更高版本，则不受此限制影响。
  • Horizon 8 不支持 vSphere 6.5 或 vSphere 6.7，因为这两个版本均已结束一般支持。Horizon 8 Instant Clones 与这些 vSphere 版本不兼容。若要使用 Instant Clones，必须先将 vSphere 升级到 7.0 或更高版本，然后再升级到 Horizon 8。

新增功能

支持 Red Hat OpenShift — 有限可用性

在 Horizon 8 2609 版本中，对 Red Hat OpenShift 的支持现已进入有限可用性（LA）阶段。有限可用性是软件发布周期中的一个阶段，表示 Horizon 8 对 Red Hat OpenShift 的支持已达到可用于生产环境的成熟度，获得 Omnissa 的全面支持，并可供经过筛选和资格审核的客户使用。这是迈向正式发布（GA）的一个阶段。由于该功能已获得 Omnissa 的全面支持，因此可用于生产环境。

管理员可以在 Red Hat OpenShift 上部署 Horizon 8 基础架构，包括 Connection Server、Unified Access Gateway 和 Edge 设备，并使用自动化和手动桌面池。如果您是 Omnissa 现有客户，希望申请使用此功能，请联系您的销售代表或合作伙伴。

Horizon Delegate — 有限可用性

Horizon Delegate 是一种 AI 代理，可代表用户在其 Horizon 虚拟桌面中执行多步骤任务。用户通过内置于 Horizon Client 的聊天界面向其分配任务。该代理使用用户自己的身份、配置文件令牌和网络权限。如果您是 Omnissa 现有客户，希望申请使用此功能，请联系您的销售代表或合作伙伴。

  • 支持的平台： vSphere 上的 Horizon 8 和 Azure 上的 Horizon Cloud。
  • 支持的桌面： Windows 单会话和多会话桌面。
  • 支持的客户端： Horizon Web Client 2609 及更高版本。暂不支持其他 Horizon Client。
  • AI 服务： 仅支持 GitHub Copilot AI 代理。您需要自行购买 GitHub Copilot 企业版席位，并将其分配给用户（自带许可证，Bring Your Own License）。
  • 许可证： 所有 Horizon 许可证均支持 Horizon Delegate。
  • 无需 GPU： Horizon Delegate 作为自主 AI 代理，直接在用户安全的 VDI 客户机操作系统会话中运行。
  • 最终用户终端无需 GPU： 用户通过直接内置于 Horizon Client 的轻量级文本聊天界面与代理交互，因此终端设备（例如瘦客户端、普通办公笔记本电脑甚至 iPhone）均无需 GPU 或额外处理能力。
  • 代理无需客户机虚拟机 vGPU： GitHub Copilot 在其云托管服务器上处理所有 AI 请求。代理本身不会在 Windows 客户机虚拟机中执行本地 LLM 推理，而是充当编排代理，负责处理多步骤工作流、运行后台任务和处理命令。基础语言模型的处理仍由安全的后端完成，因此 VDI 桌面池无需配备昂贵的 NVIDIA vGPU 来运行 Delegate。标准的受支持虚拟 CPU（vCPU）即可满足需求。
  • 管理员控制： 管理员可以针对单个桌面池或桌面池组启用 Horizon Delegate。
  • 聊天历史记录： 聊天历史记录保存在用户的本地配置文件中。

限制：

  • 不支持第三方或本地 AI 模型，例如独立运行的 OpenAI 模型、Anthropic Claude 或 Google Gemini。
  • 不支持多会话应用程序模式和 Linux 桌面。
  • 当任务在后台运行时，Horizon Delegate 无法处理多重身份验证（MFA）或条件访问提示。
  • 如果非持久性桌面意外刷新或其桌面池被重置，所有正在运行的任务都会立即停止。对于长时间运行的任务，请使用持久性桌面，并且不要应用断开连接后自动注销的策略。

Horizon Connection Server

  • Horizon Connection Server 现在会向 Horizon Client 中的 Process Manager 功能提供服务器端数据，包括会话实例 ID、应用程序或桌面名称、文件或窗口名称，以及运行状况。它还提供功能能力标志，以便管理员进行控制。

  • Omnissa Horizon Advisor 工具现在支持安装、升级和执行预检查，适用组件包括 Horizon Connection Server、Replica Server 和 Enrollment Server，并支持遥测数据收集。

  • Horizon Connection Server 现在支持为 Cloud Pod Architecture（CPA）Pod 间通信配置联盟级别的 TLS 版本和密码套件设置。这些设置存储在 Global LDAP 中，并同步到联盟中的每个 Connection Server，以避免不同 Pod 使用不同 TLS 或密码套件配置而导致 CPA 连接问题。

Horizon Console

  • 管理员现在可以直接通过 Horizon Console 配置 vdm.ec 和 vdm.enc 证书的自定义有效期。此功能使用从本版本开始提供的 REST API。

  • Horizon Admin Console 现在支持通过企业身份提供程序集成进行 SAML 2.0 身份验证，包括 Okta、PingFederate、Microsoft Entra ID 和 Secret Double Octopus。该功能支持服务提供程序（SP）发起和身份提供程序（IdP）发起的流程，并支持按 Pod 配置或共享 IdP 拓扑，同时要求提供强制性的紧急访问机制。

  • Horizon 8 应用程序池现在支持用于 Universal Broker 集成的“Cloud Managed”和“Cloud Assigned”标志，实现与桌面池相同的功能。Cloud Managed 应用程序池的授权管理将转移到 Horizon Universal Console。

  • Horizon Admin Console 现在会显示安全公告通知，涵盖 UAG、Horizon Agent 和 Connection Server。

  • Horizon Console 现在提供用于管理 SAML 签名和加密证书的功能。管理员可以通过集中式界面查看证书详细信息、监控到期日期并轮换证书。

  • Horizon Console 现在在所有数据网格中提供内联的列级筛选功能，取代此前基于模态窗口的高级筛选和自由文本搜索。这项更改减少了执行多条件查询所需的点击次数，并提供响应更迅速、符合行业标准的筛选体验。此次更新还修复了此前无法排序的网格列的排序问题。

Horizon Agent for Linux

  • “自动同步小键盘、Scroll Lock 和 Caps Lock 键”功能现已支持 Linux Agent，可在客户端终端与 Linux 桌面会话之间同步按键状态。在基于 GNOME 的 Linux Agent 上，Scroll Lock 同步功能无效。

  • Horizon Agent for Linux 中的客户端驱动器重定向功能现在会缓存目录列表，从而显著提升通过 Windows 版 Horizon Client 连接时的文件夹浏览响应速度。缓存默认启用，可通过 cdrserver.FolderCacheDisabled 选项禁用。

  • Horizon Linux Agent 中用于 USB 重定向的 VHCI 驱动程序现在集成了 DKMS，无需手动构建或应用自定义补丁。Linux 内核更新时，驱动程序会自动重新编译，从而简化安装和维护。

  • 用户现在可以在 Windows 或 Mac 版 Horizon Client 与 Linux VDI 会话之间复制和粘贴剪贴板图像，例如屏幕截图、图表和其他视觉内容，将剪贴板重定向功能从现有的文本数据扩展到图像数据。

Horizon Agent for Windows

  • 使用 ECDSA 证书进行智能卡单点登录（SSO）： Horizon Agent for Windows 现在支持使用 ECDSA 证书进行智能卡单点登录。对于 RSA 和 ECDSA 智能卡证书，Horizon Agent 现在默认使用 Windows CNG 密钥存储提供程序（KSP）。仅支持旧版 CryptoAPI 提供程序（CSP）的智能卡微型驱动程序仍可通过设置 UseCryptoAPI 使用 CSP 路径，但 ECDSA 证书必须使用 KSP 路径。

Horizon Agent for Mac — 有限可用性

  • Horizon Agent for macOS 在 2609 版本中已面向生产环境进入有限可用性（LA）阶段。管理员可以在物理 macOS 设备上安装 macOS Agent，并通过 Workspace ONE UEM 注册这些设备，以便通过 MDM 策略集中管理所需的 macOS 隐私权限，包括屏幕录制和辅助功能权限。这样，最终用户在登录 Horizon 或使用远程会话时，无需再手动批准权限提示。

Horizon 8 on Nutanix

  • 使用按需配置的 Nutanix 桌面池现在会在需要时缩减规模，以遵守桌面池的最小数量和备用数量参数。此前，未分配的虚拟机不会自动删除。

  • 单个 Nutanix 桌面池和场现在支持选择多个网络。在使用较小子网时，这可以减少需要创建的桌面池和场的数量。

  • Nutanix 桌面池现在支持 Horizon 自助终端模式（kiosk mode）。

  • Nutanix 容量提供程序现在支持通过 Omnissa Access On-premises 启动桌面和已发布的应用程序，同时继续支持现有的 Omnissa Access Cloud。

远程桌面功能

  • Horizon 现在支持客户端剪贴板控制。对于具有严格安全要求的环境，管理员除了可以在 Horizon Agent 端设置剪贴板重定向策略外，还可以在 Horizon Client 终端上强制执行这些策略，防止虚拟桌面区域覆盖相关策略。此功能默认禁用，需要通过客户端注册表设置启用。

  • Blast 网络组件现在支持使用 ECDSA 证书进行 TLS 身份验证。

  • Horizon 现在支持单独的录制回放端口，使管理员能够为会话录制和回放使用不同的端口（此前两者均使用端口 9443）。这有助于在安全敏感的环境中实施更严格的防火墙策略，例如需要将录制服务器与回放访问隔离的环境。

  • Blast Extreme 现在会自动发现网络支持的最大 UDP 数据包大小，最高可达 1500 字节，从而减少低 MTU 网络中的断开连接并提升性能。此功能默认启用，可通过注册表值或配置设置禁用。

Omnissa Horizon Windows OS Optimization Tool

  • Omnissa OS Optimization Tool（OSOT）已更新，新增适用于 Windows 11 23H2 及更高版本的优化项，包括新的 Autologger 优化类别。该类别会禁用持续运行并消耗磁盘 I/O、CPU 和内存资源的 Windows 事件跟踪（ETW）自动记录器。
