VMware ESXi - 云计算操作系统

承载虚拟机、容器和 AI 工作负载的核心基石

产品简介

VMware ESXi：专门构建的裸机 Hypervisor

了解可直接安装到您的物理服务器的、可靠的裸机 Hypervisor。通过直接访问并控制底层资源，VMware ESXi 可有效地对硬件进行分区，以便整合应用并降低成本。它是业界领先的高效体系架构 (sysin)，在可靠性、性能和支持方面树立了行业标杆。

ESXi 的优势

IT 团队肩负着适应不断波动的市场趋势并满足更高客户需求的持续压力。与此同时，他们还必须延伸 IT 资源以适应日益复杂的项目。幸运的是，原名为 ESX 的 ESXi 可帮助均衡以下两种需求：提高业务成效和实现 IT 成本节约。VMware ESXi 使您能够：

  • 整合硬件，以实现更高的容量利用率。
  • 提升性能，以获得竞争优势。
  • 通过集中管理功能精简 IT 管理。
  • 降低 CAPEX 和 OPEX。
  • 最大限度地减少运行 Hypervisor 所需的硬件资源，这意味着可以提高效率。

功能特性

ESXi 可将多台服务器整合到较少物理设备中，从而减少对空间、电力和 IT 管理的要求，同时提升性能。

  • 占用空间小
    尽管 ESXi 占用空间仅为数百 MB，却可实现更多功能 (sysin)，同时还能最大限度地降低 Hypervisor 的安全风险。

  • 可靠的性能
    适应任何规模的应用。虚拟机配置最高可达 960 个虚拟 CPU（ESX 9 提升至 960 vCPU）、24 TB 的 RAM 和 1024 台设备，以满足您的所有应用需求。咨询各项解决方案限制以确保您不会超过您环境的受支持配置。

  • 增强的安全性
    利用强大的加密功能保护敏感的虚拟机数据。基于角色的访问可简化管理，而广泛的日志记录和审核可以更好地落实责任，还可更加轻松地进行取证分析。

  • 卓越的生态系统
    获取对由硬件 OEM 供应商、技术服务合作伙伴、应用和客户机操作系统组成的广泛生态系统的支持。

  • 方便用户使用的体验
    利用基于 HTML5 标准的内置现代 UI 管理日常行政操作。对于需要实现运维自动化的客户，VMware 提供 vSphere 命令行界面和便于开发人员使用、基于 REST 的 API。

产品选项

ESXi 9 目前不再提供免费的 vSphere Hypervisor 版本，仅作为付费的 VMware vSphere Foundation (VVF) 9 和 VMware Cloud Foundation (VCF) 9 的一部分进行销售。

新增功能

VMware ESXi 9.0 GA

发布日期：2025 年 6 月 17 日

✅ 许可管理

通过 VCF Operations，将 VCF 或 vSphere Foundation 许可分配给 vCenter 实例，即可为该 vCenter 及其连接的所有组件自动授权。在未授权前，vCenter 可在评估模式下使用最长 90 天。

✅ CPU 支持

  • 支持 Sapphire Rapids 及更新的 Intel 硬件性能状态（HWP）：
    从 ESX 9.0 起，默认启用 HWP，操作系统可将 P 状态管理委托给 BIOS 而非软件管理。需在 BIOS 中开启此功能。若未启用，ESX 仍由自身代码管理 P 状态（包括 Sapphire Rapids 之前的处理器）。
  • 支持第五代 AMD EPYC 处理器（代号 Turin）。
  • 支持 Intel Granite Rapids 系列处理器，专为高性能计算设计。

✅ 加速器 (Accelerators)

  • 内存分层（Memory Tiering）：
    ESX 9.0 正式推出内存分层功能，可将本地 NVMe 设备作为分层内存添加至 ESX 主机，实现 VM 内存页在 DRAM 和 NVMe 设备间动态分配，提升 CPU 利用率和工作负载容量，降低总体拥有成本。
  • 增强型 vGPU 设备的设备选择策略：
    可通过 vSphere Client 配置设备分配策略，选择性能优先（均匀分配 VF）或整合优先（集中分配 VF），以优化硬件利用。
  • 增强型 DirectPath I/O 设备的自动重配置：
    支持自动根据 VM 需求在电源启动或迁移时透明切换多配置文件或功能的设备，无需管理员手动操作。
  • vGPU 工作负载的 vSphere vMotion 优化：
    利用 Intel 和 AMD CPU 的 IOMMU Dirty Bit 技术，减少 vGPU VM 的停机时间。
  • 支持非检查点设备的增强型 DirectPath I/O：
    支持在带增强型 DirectPath I/O 的虚拟机上热添加内存、vCPU、虚拟设备（NIC），启用调试和统计功能，支持 Storage vMotion。典型设备包括 Intel 动态负载均衡器（DLB）和 AMD MI200 GPU。
  • 增强型 DirectPath I/O 的虚拟 IOMMU 支持：
    为使用增强型 DirectPath I/O 的虚拟机提供虚拟输入输出内存管理单元（vIOMMU），提高客户操作系统应用的安全性。

✅ 工作负载支持的客户操作系统

新增支持以下操作系统：

  • Pardus
  • Red Hat Core OS
  • Miracle Linux
  • ProLinux
  • 麒麟（Kylin）Linux
  • FusionOS
  • RHEL 10
  • Oracle Linux 10
  • Debian 13
  • FreeBSD 15

✅ 虚拟硬件版本 22

vCenter 9.0 引入虚拟硬件版本 22，支持最新客户操作系统并提高最大配置：

  • 支持最大 960 个逻辑处理器
  • 支持最大每插槽 960 个核心
    新增支持操作系统：ProLinux、FusionOS、Kylin、Miracle Linux
    新增支持功能包括：
  • 所有直通设备的点对点功能
  • NVMe 1.4
  • Intel Trust Domain Extensions (TDX)
  • AMD 新一代 SEV-SNP（安全嵌套分页）
  • Intel Granite Rapids 和 AMD 第五代 EPYC 新指令集支持
  • 支持 4KN VMDK 和 4KN 本地驱动器
  • 增强型 DirectPath I/O 的虚拟 I/O MMU
  • 实时虚拟交换机

✅ Span Limit 策略

允许你为一组虚拟机设定亲和关系到指定数量的主机，而无需明确指定主机列表。

✅ 驱动程序

支持 Broadcom 9700 系列 RAID 控制卡和增强主机总线适配器（eHBA）：

  • RAID：SAS SSD，NVMe SSD
  • eHBA：SAS HDD，SAS SSD，SATA HDD，SATA SSD

驱动初始内存保留降为零（除不可行或不适用的情况），降低内存开销。

更新驱动及修复漏洞包括：

  • Broadcom: bcm_mpi3、lsi_msgpt35、lsi_mr3、lpfc
  • Cisco: nfnic、nenic-ens
  • Intel: i40en、iavmd
  • Marvell: qlnativefc
  • Mellanox: nmlx5
  • Microchip: smartpqi
  • Pensando: ionic_en
  • VMware: vmxnet3_ens

Broadcom bcm_mpi3 驱动新增对 4K 原生模式 SSD 支持。

Cisco nenic_ens 驱动支持 Enhanced Data Path（EDP）。

Intel icen 驱动新增对 NetQ RSS for EDP 支持。

Mellanox nmlx5 驱动新增 400G 支持及性能优化，支持 NSX 隧道终端（TEP）及原位升级，VXLAN UDP 端口支持。

VMware vmxnet3_ens 驱动将虚拟硬件标准由版本 3 升级到 6，支持 Geneve 泛网络虚拟化封装卸载、VXLAN 卸载、RSS 和 LRO。

例行驱动更新和修复同样涵盖上述厂商部分驱动。

ESX USB 驱动支持通信设备类网络控制模型（CDC-NCM）协议，兼容 HPE Gen12 iLO 虚拟网卡及多种 HPE 管理工具。

支持 Windows 显示驱动模型（WDDM）2.0。

✅ 存储

  • 支持通过最新 NVMe/Fibre Channel (FC) 启动 ESX，实现基于 SAN 存储的远程 NVMe 启动，提升灵活性和性能。
  • 支持 NVMe/TCP（设备规范 TP-8012）启动，扩展 SAN 启动方案，简化远程 NVMe/TCP 存储部署和管理。
  • 快照功能增强，精确跟踪合并进度并支持离线 VM 快照合并恢复。
  • 虚拟 NVMe 支持命名空间写保护（只读磁盘），支持热添加独立非持久磁盘，无需创建差异磁盘，加快应用交付。
  • 支持带 ESX-OSData 分区的远程启动设备及关键故障监控。若关键故障无法恢复，ESX 将停止并显示紫屏诊断，防止系统损坏

✅ 网络

ESX 内置 NSX VIB（虚拟网络内核模块）并支持 Live Patch，简化安装升级流程，无需进入维护模式且不影响 vMotion 或 DRS 操作。

名称变更

B 公司为了与 VMware 区分，将版本 9 中的 ESXi 名称修改为 ESX，虽然 B 公司用词为 ESX 9，但是实际技术依然是 ESXi（并不是 ESX，ESX 是 VMware 早期发布的 Linux 版本），并且 B 公司对名称的修改也并不彻底，文档中虽然改为了 ESX，但实际的软件名称仍然是 ESXi。

本站根据 VMware 惯例以及技术导向和实事求是的原则，继续用名 ESXi。
