VMware ESXi - 领先的裸机 Hypervisor

产品简介

VMware ESXi：专门构建的裸机 Hypervisor

了解可直接安装到您的物理服务器的、可靠的裸机 Hypervisor。通过直接访问并控制底层资源，VMware ESXi 可有效地对硬件进行分区，以便整合应用并降低成本。它是业界领先的高效体系架构 (sysin)，在可靠性、性能和支持方面树立了行业标杆。

ESXi 的优势

IT 团队肩负着适应不断波动的市场趋势并满足更高客户需求的持续压力。与此同时，他们还必须延伸 IT 资源以适应日益复杂的项目。幸运的是，原名为 ESX 的 ESXi 可帮助均衡以下两种需求：提高业务成效和实现 IT 成本节约。VMware ESXi 使您能够：

  • 整合硬件，以实现更高的容量利用率。
  • 提升性能，以获得竞争优势。
  • 通过集中管理功能精简 IT 管理。
  • 降低 CAPEX 和 OPEX。
  • 最大限度地减少运行 Hypervisor 所需的硬件资源，这意味着可以提高效率。

功能特性

ESXi 可将多台服务器整合到较少物理设备中，从而减少对空间、电力和 IT 管理的要求，同时提升性能。

  • 占用空间小
    尽管 ESXi 占用空间仅为数百 MB，却可实现更多功能 (sysin)，同时还能最大限度地降低 Hypervisor 的安全风险。

  • 可靠的性能
    适应任何规模的应用。虚拟机配置最高可达 768 个虚拟 CPU、24 TB 的 RAM 和 1024 台设备，以满足您的所有应用需求。咨询各项解决方案限制以确保您不会超过您环境的受支持配置。

  • 增强的安全性
    利用强大的加密功能保护敏感的虚拟机数据。基于角色的访问可简化管理，而广泛的日志记录和审核可以更好地落实责任，还可更加轻松地进行取证分析。

  • 卓越的生态系统
    获取对由硬件 OEM 供应商、技术服务合作伙伴、应用和客户机操作系统组成的广泛生态系统的支持。

  • 方便用户使用的体验
    利用基于 HTML5 标准的内置现代 UI 管理日常行政操作。对于需要实现运维自动化的客户，VMware 提供 vSphere 命令行界面和便于开发人员使用、基于 REST 的 API。

产品选项

客户可以将 ESXi (ESX) 作为付费 vSphere 版本的一部分使用或与免费的 vSphere Hypervisor 版本配合使用，这样，您便可以在几分钟内轻松创建并置备虚拟机。

那么什么是 ESXi-Arm？这一切的目标是什么？这里有很多东西要解开，所以让我们开始吧。

ESXi-Arm 是什么

顾名思义，ESXi-Arm 是专为在 64 位 Arm 处理器上运行而构建的 ESXi 版本。传统上，ESXi 是为 x86 计算虚拟化而设计的。然而，几年前，VMware 的一个 Arm 专家小组开始致力于将 ESXi 移植到 Arm。这是一项艰巨的技术任务。ESXi 不仅是一个庞大的代码库，具有许多技术细节，而且 Arm 处理器的底层语义与 x86 也大不相同 (sysin)。这需要仔细测试和修改，以确保 ESXi 在 Arm 和 x86 平台上运行，同时保持 ESXi 的高标准。

VMware 与 Arm 密切合作, 通过他们的 Project Cassini，让 ESXi-Arm 在广泛的设备上启动和运行，以涵盖数据中心、边缘计算等。这项工作包括将硬件标准、固件标准和认证扩展到现有 Arm 服务器生态系统之外，这使 VMware 能够支持 SmartNIC 和无处不在的 RaspberryPi 等平台。VMware 甚至在驱动程序方面进行了合作。

除了技术挑战之外，VMware 还探索了使用 Arm 处理器的用例。在过去的几年中，您已经看到 VMware 在 VMworld 上展示了许多不同的用例：风力涡轮机上的任务关键型工作负载，使用 SmartNIC、vSAN 存储服务器和见证设备在单个物理服务器上运行 ESXi 主机集群，并在云中的 AWS Graviton 上运行。在 VMware 与客户和合作伙伴交谈时，一个迅速上升到顶端的用例是在 SmartNIC 上的 Arm 处理器上运行 ESXi。因此，VMware 启动了一个项目来实现它：Project Monterey。

Project Monterey (蒙特雷计划)

2020 年 9 月 30 日

VMware 上周在 VMworld 上宣布了 Project Monterey。这是对 VMware Cloud Foundation 底层硬件架构的重新思考。特别是，Project Monterey 为 VMware Cloud Foundation 添加了 SmartNIC 支持 (sysin)。这可以提供一些强大的用例：改进的网络性能、零信任安全、存储加速、vSphere 中的裸机支持 (!!) 以及通过可组合性进行硬件分解。这一切都是由在 SmartNIC 上运行的 ESXi 实现的，特别是在基于 Arm 的 SmartNIC 上。

这是 ESXi-Arm 的第一个用例——支持在 SmartNIC 上运行的 ESXi，以提供 Project Monterey 的所有这些巨大优势。VMware 已经在与客户合作，以更好地了解他们对 Project Monterey 和 SmartNIC 的需求。但是，VMware 想更多地了解客户希望使用 ESXi-Arm 的其他方式。这让 VMware 陷入困境。

系统要求

ESXi-Arm 代码库从 7.x 移植到 8.x 之后，该团队还继续支持各种基于 Arm 的系统，列表如下：

  • 基于 Ampere Computing Altra 和 AltraMax 的服务器（单处理器系统，如 HPE ProLiant RL300 Gen 11 或双处理器系统，如 Ampere 2U Mt. Collins）
  • 基于 NXP LayerScape 2160A 的 SolidRun HoneyComb LX2K mini-ITX 平台。
  • Raspberry Pi 4B（仅限 8GB）
  • Raspberry Pi 5（仅限 8GB）
  • 基于 Rockchip RK3566 的 PINE64 Quartz64 Model A 和 SOQuartz 计算模块
  • 基于 Rockchip RK3566 的 Firefly ROC-RK3566-PC 和 StationPC Station M2

备注：不支持运行在 Apple silicon 裸机之上，但是可以在搭载 Apple 芯片的 Mac 上，作为 VMware Fusion 的嵌套虚拟化实例运行。
